# 카카오 메시지 필터 · Android 0.1.5

Android 8.0(API 26) 이상을 대상으로 만든 **접근성 기반 시제품**입니다. PC와 같은 숨김 목록/채팅방 설정을 사용하지만 Android의 접근성 서비스와 가림막으로 별도 구현했습니다. 카카오톡 내부 파일이나 서버 메시지를 바꾸지 않습니다.

**실제 카카오톡 기기에서의 호환성은 아직 검증하지 않았습니다.** 카카오톡이 접근성에 발신자·메시지 위치를 제공해야 작동합니다. 0.1.5는 Android 14 이상에서 별도 동의를 받아 흰색 수신/노란색 발신 말풍선을 화면 분석하고, 확인한 메시지 표식을 실행 중 기억하는 선택 기능을 추가했습니다. 발신자 확인에는 접근성 정보가 필요하며 OCR은 사용하지 않습니다.

## 메시지 기억과 연속 말풍선 보완 (0.1.5)

기존 방식은 현재 화면의 이름을 매번 확인했기 때문에 이름이 화면 밖으로 나가면 가림이 풀렸습니다. 접근성 노드에 다음 말풍선의 영역이 없으면 첫 메시지만 가려질 수도 있었습니다. 0.1.5는 사용자가 **메시지 기억 · 연속 말풍선 보완 (화면 분석 사용)**을 켜고 동의한 경우 다음 경로를 추가합니다.

- Android 14의 `takeScreenshotOfWindow`로 전면 카카오톡 창만 읽습니다. 접근성 가림막이 제외된 창 이미지를 분석하므로 가림막 자체를 메시지로 기억하지 않습니다. 다른 앱이나 보안 처리된 창은 촬영하지 않으며 보호를 우회하지 않습니다.
- 기본 밝은 테마의 연결된 흰색 수신/노란색 발신 말풍선 영역을 찾아 현재 발신자 구간에 연결합니다. 이 경로는 메시지 본문 노드가 없어도 다음 흰색 말풍선을 보완합니다. 접근성으로 다음 발신자 경계를 못 찾은 경우의 정확성은 기기 확인이 필요합니다.
- 이름으로 확인한 메시지는 실행마다 새 임의값으로 만든 시각적 해시와 이웃 메시지 표식으로 기억합니다. 스크롤 후 이름이 없어도 동일한 표식과 문맥이 맞으면 현재 위치에 다시 가립니다. 다른 발신자가 확인되거나 같은 내용이 중복되어 소유자가 불분명하면 기억만으로 이어 가리지 않습니다.
- Android가 픽셀 스크롤 이동량을 제공하면 가림막을 즉시 같은 방향으로 이동합니다. 화면 끝에서 일부가 잘린 말풍선은 이동한 영역과 정확히 일치하는 텍스트 행 해시가 있을 때만 기억을 재사용합니다. 이동량이 없으면 고정된 옛 좌표를 유지하지 않습니다.
- 원본 이미지와 픽셀 배열은 처리 후 폐기합니다. 메시지/이미지/해시는 디스크·로그·진단 JSON에 저장하거나 외부 전송하지 않습니다. 표식은 최대 2,000개이며 앱/서비스 종료, 설정 변경, 다른 방/창 크기로의 전환 때 초기화됩니다. 카카오톡 메시지를 서버에서 삭제하거나 영구적으로 수정하는 기능은 아닙니다.

**업데이트 후 접근성 서비스를 한 번 껐다 켜세요.** 새 화면 분석 기능을 읽으려면 서비스 재연결이 필요할 수 있습니다. 앱에서 위 옵션에 동의한 뒤 설정을 저장하고, 대상 이름과 말풍선이 함께 보이는 화면을 한 번 연 다음 스크롤하세요. 통계의 `화면 말풍선 · 기억 · 기억 재사용` 개수로 동작을 확인할 수 있습니다. 설정 JSON을 가져와도 화면 분석 옵션은 OFF로 적용하여 자동으로 동의하지 않게 했습니다.

사용자가 제공한 886.jpg에서 노출된 연속 흰색 말풍선 두 개를 탐지하는 것을 확인했고 원본 사진은 저장소에 넣지 않았습니다. JVM 테스트는 가상 픽셀/노드/스크롤 데이터로 기억 재사용과 다른 사람 제외를 확인합니다. 실제 S25 접근성·창 촬영·스크롤 이벤트 조합은 이 환경에서 실행하지 못했습니다. 테마/글꼴/크기 변경, 동일한 내용과 이웃이 반복되는 경우, 빠른 움직임, 메시지 수정 등에서는 기억이 적용되지 않거나 오차가 날 수 있습니다. 순간 노출이 전혀 없음을 보장하지 않습니다.

## 스크롤 후 가림막 재확인 (0.1.4)

이전 버전은 레이아웃 이벤트를 받은 뒤 한 번만 읽었습니다. 그 순간 목록이 갱신 중이거나 접근성 캐시에 이전 노드가 남으면, 다음 이벤트가 없을 때 가림막이 돌아오지 않을 수 있었습니다. 0.1.4는 Android 13 이상에서 읽기 전 접근성 캐시를 갱신하며, 스크롤 이벤트 후 1.5초 동안 스캔 완료 후 100ms 간격으로 다시 읽습니다. 이후 카카오톡이 전면에 있으면 400ms 간격으로 확인합니다. 새 이벤트가 오면 예정된 느린 갱신을 앞당깁니다. 실제 반영 시간에는 화면 읽기·그리기 시간이 추가됩니다.

전면 창을 일시적으로 못 읽으면 최근 카카오톡 확인 후 최대 1.5초까지만 재시도하고, 다른 앱/화면 꺼짐/잠금/필터 OFF에서는 멈춥니다. 이전 좌표를 그대로 유지하거나 화면 밖 발신자를 추측하지 않습니다. 따라서 이름과 프로필이 화면 위로 사라진 경우와 스크롤 중 순간 노출은 별도 한계로 남습니다.

가상 시계 테스트로 추가 이벤트 없는 갱신, 예약 앞당김, 일시적인 창 누락 후 복구, 재시도 종료와 앱 전환 시 중지를 확인했습니다. JVM 테스트 총 32개와 Lint 검증 범위이며 실제 S25에서 해결됐다는 보장은 아닙니다.

계속 첫 말풍선만 가려지거나 스크롤 후 남아 있으면, 필터 앱 **상단**의 **문제 화면 진단 시작 → 카카오톡에서 문제 메시지가 보이는 화면 열기 → 필터 앱으로 돌아오기 → 진단 파일 저장**을 사용하세요. `kakao-screen-structure.json`을 이 대화에 첨부하면 실제 노드 경계를 확인할 수 있습니다. 0.1.4 진단에는 판단에 사용한 채팅 영역/가림막 좌표와 시간·읽지 않은 개수 여부를 추가했습니다. 메시지·닉네임 원문은 포함하지 않습니다.

## 연속 메시지 중 첫 메시지만 가려지는 경우 (0.1.3)

일부 접근성 레이아웃에서 첫 메시지는 단일 노드로 보이고 다음 메시지는 자식 요소가 있는 컨테이너로 제공되면, 기존의 리소스 ID/말단 노드 조건 때문에 다음 메시지를 건너뛰었습니다. 이 형식에서 첫 메시지만 가려지는 케이스 두 개를 재현해 수정했습니다. 사용자가 보내준 실제 기기의 노드 진단을 받은 것은 아니므로, 화면에 보인 현상의 원인이 반드시 이 케이스라고 단정하지는 않습니다.

0.1.3은 현재 프레임에서 확인한 발신자 구간 안에서 메시지 본문/접근성 설명을 가진 컨테이너도 처리하고, 같은 메시지 행에 설명이 있는 경우 빈 말풍선 영역도 연결합니다. 내 발신 메시지나 편집 입력을 포함한 부모 전체를 한꺼번에 가리지 않도록 제외하며, 다음 사람/이름을 읽지 못한 새 프로필에서 구간을 끊는 규칙은 유지합니다.

업데이트 설치 후 같은 대화방의 연속 메시지를 확인하세요. 여전히 첫 메시지만 가려지면, 가려지지 않은 말풍선이 보이는 상태의 구조 진단 JSON이 필요합니다. 다른 사람의 메시지까지 이어 가리지 않도록 실제 노드 경계를 확인한 뒤 수정해야 합니다.

## 발신자는 있는데 대상/가림막이 0일 때 (0.1.2 이후)

`발신자 2 · 대상 0 · 가림막 0`은 읽은 이름이 숨김 목록과 다르거나, 일치하는 이름의 프로필이 화면에서 잘린 경우에 나올 수 있습니다. 0.1.2는 실제 인식 이름을 확인하고 선택해 추가하는 기능과 원인별 안내를 제공합니다.

1. 최신 APK로 업데이트하고 접근성 서비스가 켜져 있는지 확인합니다.
2. **인식한 닉네임 표시**를 켭니다. 이 옵션은 기본 OFF이며 켠 동안 이름을 메모리에만 유지합니다.
3. 대상의 이름과 프로필이 완전히 보이는 카카오톡 채팅방을 열었다가 필터 앱으로 돌아옵니다.
4. **인식한 이름 선택해서 숨김 목록에 추가**에서 실제 대상을 선택합니다. 선택한 값이 이미 목록에 있으면 프로필 잘림/메시지 영역 안내를 확인합니다. 다른 사람을 잘못 선택하지 마세요.
5. **설정 저장 및 적용** 후 다시 카카오톡을 엽니다. 표시한 이름을 숨김 목록에 추가하고 저장한 경우에만 설정에 영구 보관됩니다.

이름이 목록에 없거나 여전히 안 가려지면 **문제 화면 진단 시작 → 카카오톡 채팅방 열기 → 필터 앱으로 돌아오기 → 진단 파일 저장**을 사용하세요. 저장한 `kakao-screen-structure.json`은 노드 ID/클래스/좌표/문자열 길이/일치 여부 등 구조만 포함합니다. 메시지·닉네임·채팅방 제목·접근성 설명 원문은 포함하지 않습니다. 사용자가 진단을 시작한 한 프레임만 메모리에 저장하고, 파일은 저장 버튼을 눌렀을 때만 만듭니다. 자동 전송은 없습니다.

일반 접근성 탐색에서 생략되던 뷰도 읽도록 지원 플래그를 추가했습니다. Android가 보호해 제공하지 않는 정보를 우회해서 읽는 기능은 아니며, 실제 S25 카카오톡 호환성은 아직 기기 확인이 필요합니다. 설정 앱으로 돌아왔을 때 ‘다른 앱/설정 화면’이라고 표시되는 것은 정상이며 마지막 카카오톡 결과와 구분됩니다.

## 현재 구현

- 숨김 닉네임 목록, 정확 일치/NFC 정규화, 방 제목 범위, 켜기/끄기
- 접근성에 노출된 프로필/발신자를 기준으로 같은 프레임의 메시지 그룹 판별
- 사진·이모티콘과 이름이 생략된 연속 메시지 연결
- 다음 프로필에서 그룹 종료: 이름을 읽지 못한 다음 프로필도 경계로 사용
- 가로로 긴 메시지를 화면의 고정 비율로 자르지 않고 전체 좌표 사용
- 클릭·스크롤이 통과되는 완전 가림/안내문
- 스크롤·내용 변경 이벤트와 전면 주기 확인에 따른 갱신, 기억 옵션에서 이동량에 따른 즉시 좌표 이동, 다른 앱 전환/화면 꺼짐/잠금 시 제거
- 옛 좌표를 고정하지 않고 현재 말풍선/표식/이웃 문맥 및 측정된 스크롤 이동량으로 기억 재사용
- PC JSON 설정 가져오기/내보내기

접근성 가림막(`TYPE_ACCESSIBILITY_OVERLAY`)을 사용하므로 **별도 ‘다른 앱 위에 표시’ 권한은 필요하지 않습니다.** 화면 녹화/사진·파일 접근/인터넷 권한도 요청하지 않습니다. 선택 화면 분석은 별도 앱 내 동의 후 접근성 서비스의 창 촬영 기능을 사용합니다. 완전 가림은 불투명하게 그립니다. Android 12의 일반 앱 오버레이 터치 제한을 피하려고 불투명도를 낮추는 방식은 사용하지 않습니다.

## 한계와 확인 방법

- 발신자 0: 접근성 이름/프로필 정보가 없거나, 현재 화면 구조가 지원하는 형태와 다를 수 있습니다. 특정 카카오톡 버전에서 동작을 보장하지 않습니다.
- 대상 0: 실제 접근성 이름이 숨김 목록과 다르거나 선택한 방 제목을 확인하지 못했을 수 있습니다. 이름을 정확히 입력하고 테스트 방에서 범위를 확인하세요.
- 가림막 0: 접근성에서 메시지 영역을 찾지 못했거나 지원하지 않는 배치일 수 있습니다.
- 채팅 입력창이 보이는 대화방에서만 처리합니다. 친구/채팅방 목록을 가리지 않도록 입력창 확인을 요구합니다.
- 이름/프로필이 화면 위로 사라지면, 기억 옵션으로 앞서 확인한 메시지의 표식·문맥을 맞출 수 있을 때 재사용합니다. 처음부터 발신자를 못 읽은 메시지나 표식이 바뀐 메시지는 기억할 수 없습니다.
- 사진·답장·이모티콘 등의 접근성 구조는 버전마다 달라 누락 또는 영역 오차가 있을 수 있습니다. 복잡한 답장/테마/팝업/분할 화면은 기기 검증이 필요합니다.
- 스크롤 중 잠깐 노출될 수 있습니다. 메시지를 한순간도 볼 수 없게 하는 보안 도구는 아닙니다.
- 흐림은 미구현입니다. PC JSON의 `blur`를 가져오면 완전 가림으로 바꿉니다.
- 실제 Android 기기/에뮬레이터와 카카오톡 계정에서의 동작 검사는 이 클라우드에서 실행하지 않았습니다.

## 개인정보

서비스는 카카오톡이 전면에 있을 때만 그 앱의 접근성 트리를 읽습니다. 사용자가 화면 분석 옵션에 별도 동의한 경우에만 그 카카오톡 창 이미지도 메모리에서 분석합니다. 원본 이미지/픽셀 배열은 처리 후 폐기하고, 기억용 시각적 표식은 메모리에만 유지합니다. 앱/서비스 종료 시 사라지며 백업·외부 전송·디스크 저장하지 않습니다. 메시지 내용은 화면 구조를 판별하는 동안 메모리에서만 사용하고 저장·로그·외부 전송하지 않습니다. 다른 앱은 전면 패키지 이름만 확인하고 대화 트리를 읽지 않습니다. 기본 통계 화면에는 개수와 상태만 표시합니다. 진단용 이름 표시를 직접 켠 경우 발신자 이름을 메모리에 유지해 보여주며, 끄면 지웁니다. 구조 진단 파일은 별도 요청/저장 동작이 있을 때만 생성합니다.

설정의 닉네임/방 제목은 앱 내부 SharedPreferences에 평문 JSON으로 저장됩니다. 자동 백업은 끄며 삭제하면 설정도 사라집니다. 사용자가 내보내기를 요청한 JSON에는 숨김 목록과 옵션이 포함됩니다. 파일을 안전하게 보관하세요. 가져온 설정은 필터 OFF 및 화면 분석 OFF 상태로 적용하며 내용을 확인한 후 직접 켜야 합니다.

## 소스 빌드

Android Studio에서 이 `android` 폴더를 열면 됩니다. JDK 17 또는 21, Android SDK Platform 35 및 Build Tools 35.0.0이 필요합니다. 사용한 도구는 AGP 8.9.2 / Kotlin 2.1.20 / Gradle 8.11.1 / JDK 21입니다. Gradle Wrapper에 배포 ZIP의 SHA-256 검증을 설정했습니다.

Windows PowerShell:

```powershell
cd android
.\gradlew.bat :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

Linux/macOS:

```sh
cd android
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

SDK 경로는 Android Studio가 만든 `local.properties` 또는 `ANDROID_HOME`으로 설정하세요. `local.properties`, 빌드 캐시, 서명 키는 저장소에 넣지 않습니다.

일반 설치용 출력: `app/build/outputs/apk/release/app-release.apk`

디버그 빌드가 필요하면 `:app:assembleDebug`를 실행합니다. 출력은 `app/build/outputs/apk/debug/app-debug.apk`입니다. 저장소의 기본 release 서명도 개발용 키를 사용하므로 정식 배포를 준비할 때는 별도로 보관·관리하는 배포 키와 업데이트 계획이 필요합니다.

## 검증 범위

JVM 단위 테스트는 발신자/사진/연속 메시지 연결, 읽지 못한 프로필 경계, 다른 사람의 본문에 포함된 닉네임, 넓은 메시지, 방 범위, 필터 OFF, 편집 입력/명시된 발신 메시지 제외, 현재 스크롤 좌표를 검사합니다. 빌드와 Android Lint는 Android API/리소스/매니페스트 구성도 검사합니다. 이 검증이 실제 카카오톡 접근성 호환성을 입증하지는 않습니다.

실제 기기에서는 다음을 확인하세요.

- [ ] 대상/비대상, 동명이인, 사진·이모티콘·답장·긴 메시지
- [ ] 스크롤·방 전환·가로/세로 회전 후 좌표
- [ ] 가림막 위 클릭·휠/스와이프·메시지 입력
- [ ] 다른 앱·친구 목록·잠금 화면에서 가림막 제거
- [ ] 필터 OFF/접근성 권한 해제 후 제거
- [ ] PC JSON 가져오기/내보내기와 앱 업데이트
