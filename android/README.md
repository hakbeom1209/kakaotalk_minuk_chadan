# 카카오 메시지 필터 · Android 0.1.3

Android 8.0(API 26) 이상을 대상으로 만든 **접근성 기반 시제품**입니다. PC와 같은 숨김 목록/채팅방 설정을 사용하지만 Android의 접근성 서비스와 가림막으로 별도 구현했습니다. 카카오톡 내부 파일이나 서버 메시지를 바꾸지 않습니다.

**실제 카카오톡 기기에서의 호환성은 아직 검증하지 않았습니다.** 카카오톡이 접근성에 발신자·메시지 위치를 제공해야 작동합니다. 정보가 없으면 추측해서 가리지 않으며 현재 버전에는 OCR/화면 캡처 대체 경로가 없습니다.

## ‘앱이 설치되지 않았습니다’가 나올 때

- 위 링크의 `KakaoMessageFilter-Android-0.1.3.apk`를 새로 받아 설치합니다. 예전 debug 파일을 다시 여는 것과 구분하세요.
- Android 16 / 64비트 전용 기기도 SDK/ABI 지원 범위에 들어갑니다. 네이티브 라이브러리가 없는 공용 APK입니다.
- 삼성 기기에서는 **설정 → 보안 및 개인정보 보호 → 자동 차단** 상태를 확인합니다. 외부 APK 설치를 제한하는 설정이 원인일 수 있습니다. 상태만으로 단정하지 말고 설치 화면의 구체적인 안내도 확인하세요.
- 설치되지 않았던 앱이라면 삭제할 기존 앱은 없습니다. 기존 앱이 있을 때는 서명 충돌 가능성을 확인하고 설정을 백업하기 전 무작정 삭제하지 마세요.
- 계속 실패하면 ‘앱이 설치되지 않았습니다’ 한 줄만으로 원인을 알 수 없습니다. USB 디버깅을 이미 사용하는 개발 환경에서는 다음 명령의 `INSTALL_FAILED_...` 결과가 정확한 원인 확인에 도움이 됩니다. 기기 연결/디버깅 승인은 사용자가 직접 해야 합니다.


## 연속 메시지 중 첫 메시지만 가려지는 경우 (0.1.3)

일부 접근성 레이아웃에서 첫 메시지는 단일 노드로 보이고 다음 메시지는 자식 요소가 있는 컨테이너로 제공되면, 기존의 리소스 ID/말단 노드 조건 때문에 다음 메시지를 건너뛰었습니다. 이 형식에서 첫 메시지만 가려지는 케이스 두 개를 재현해 수정했습니다. 사용자가 보내준 실제 기기의 노드 진단을 받은 것은 아니므로, 화면에 보인 현상의 원인이 반드시 이 케이스라고 단정하지는 않습니다.

0.1.3은 현재 프레임에서 확인한 발신자 구간 안에서 메시지 본문/접근성 설명을 가진 컨테이너도 처리하고, 같은 메시지 행에 설명이 있는 경우 빈 말풍선 영역도 연결합니다. 내 발신 메시지나 편집 입력을 포함한 부모 전체를 한꺼번에 가리지 않도록 제외하며, 다음 사람/이름을 읽지 못한 새 프로필에서 구간을 끊는 규칙은 유지합니다.

업데이트 설치 후 같은 대화방의 연속 메시지를 확인하세요. 여전히 첫 메시지만 가려지면, 가려지지 않은 말풍선이 보이는 상태의 구조 진단 JSON이 필요합니다. 다른 사람의 메시지까지 이어 가리지 않도록 실제 노드 경계를 확인한 뒤 수정해야 합니다.

## 발신자는 있는데 대상/가림막이 0일 때 (0.1.2 이후)

`발신자 2 · 대상 0 · 가림막 0`은 읽은 이름이 숨김 목록과 다르거나, 일치하는 이름의 프로필이 화면에서 잘린 경우에 나올 수 있습니다. 0.1.2는 실제 인식 이름을 확인하고 선택해 추가하는 기능과 원인별 안내를 제공합니다.

1. 최신 APK로 업데이트하고 접근성 서비스가 켜져 있는지 확인합니다.
2. **인식한 닉네임 표시**를 켭니다. 이 옵션은 기본 OFF이며 켠 동안 이름을 메모리에만 유지합니다.
3. 대상의 이름과 프로필이 완전히 보이는 카카오톡 채팅방을 열었다가 필터 앱으로 돌아옵니다.
4. **인식한 이름 선택해서 숨김 목록에 추가**에서 실제 대상을 선택합니다. 선택한 값이 이미 목록에 있으면 프로필 잘림/메시지 영역 안내를 확인합니다. 다른 사람을 잘못 선택하지 마세요.
5. **설정 저장 및 적용** 후 다시 카카오톡을 엽니다. 표시한 이름을 숨김 목록에 추가하고 저장한 경우에만 설정에 영구 보관됩니다.

이름이 목록에 없거나 여전히 안 가려지면 **카카오톡 화면 구조 진단 시작 → 카카오톡 채팅방 열기 → 필터 앱으로 돌아오기 → 진단 파일 저장**을 사용하세요. 저장한 `kakao-screen-structure.json`은 노드 ID/클래스/좌표/문자열 길이/일치 여부 등 구조만 포함합니다. 메시지·닉네임·채팅방 제목·접근성 설명 원문은 포함하지 않습니다. 사용자가 진단을 시작한 한 프레임만 메모리에 저장하고, 파일은 저장 버튼을 눌렀을 때만 만듭니다. 자동 전송은 없습니다.

일반 접근성 탐색에서 생략되던 뷰도 읽도록 지원 플래그를 추가했습니다. Android가 보호해 제공하지 않는 정보를 우회해서 읽는 기능은 아니며, 실제 S25 카카오톡 호환성은 아직 기기 확인이 필요합니다. 설정 앱으로 돌아왔을 때 ‘다른 앱/설정 화면’이라고 표시되는 것은 정상이며 마지막 카카오톡 결과와 구분됩니다.

## 현재 구현

- 숨김 닉네임 목록, 정확 일치/NFC 정규화, 방 제목 범위, 켜기/끄기
- 접근성에 노출된 프로필/발신자를 기준으로 같은 프레임의 메시지 그룹 판별
- 사진·이모티콘과 이름이 생략된 연속 메시지 연결
- 다음 프로필에서 그룹 종료: 이름을 읽지 못한 다음 프로필도 경계로 사용
- 가로로 긴 메시지를 화면의 고정 비율로 자르지 않고 전체 좌표 사용
- 클릭·스크롤이 통과되는 완전 가림/안내문
- 스크롤·내용 변경 이벤트에 맞춘 갱신, 다른 앱 전환/화면 꺼짐/잠금 시 제거
- 화면에 좌표가 없는 이전 프레임의 발신자나 메시지 위치를 이어 붙이지 않음
- PC JSON 설정 가져오기/내보내기

접근성 가림막(`TYPE_ACCESSIBILITY_OVERLAY`)을 사용하므로 **별도 ‘다른 앱 위에 표시’ 권한은 필요하지 않습니다.** 화면 녹화/사진·파일 접근/인터넷 권한도 요청하지 않습니다. 완전 가림은 불투명하게 그립니다. Android 12의 일반 앱 오버레이 터치 제한을 피하려고 불투명도를 낮추는 방식은 사용하지 않습니다.

## 한계와 확인 방법

- 발신자 0: 접근성 이름/프로필 정보가 없거나, 현재 화면 구조가 지원하는 형태와 다를 수 있습니다. 특정 카카오톡 버전에서 동작을 보장하지 않습니다.
- 대상 0: 실제 접근성 이름이 숨김 목록과 다르거나 선택한 방 제목을 확인하지 못했을 수 있습니다. 이름을 정확히 입력하고 테스트 방에서 범위를 확인하세요.
- 가림막 0: 접근성에서 메시지 영역을 찾지 못했거나 지원하지 않는 배치일 수 있습니다.
- 채팅 입력창이 보이는 대화방에서만 처리합니다. 친구/채팅방 목록을 가리지 않도록 입력창 확인을 요구합니다.
- 이름/프로필이 화면 위로 사라진 메시지는 소유자를 추측하지 않습니다.
- 사진·답장·이모티콘 등의 접근성 구조는 버전마다 달라 누락 또는 영역 오차가 있을 수 있습니다. 복잡한 답장/테마/팝업/분할 화면은 기기 검증이 필요합니다.
- 스크롤 중 잠깐 노출될 수 있습니다. 메시지를 한순간도 볼 수 없게 하는 보안 도구는 아닙니다.
- 흐림은 미구현입니다. PC JSON의 `blur`를 가져오면 완전 가림으로 바꿉니다.
- 실제 Android 기기/에뮬레이터와 카카오톡 계정에서의 동작 검사는 이 클라우드에서 실행하지 않았습니다.

## 개인정보

서비스는 카카오톡이 전면에 있을 때만 그 앱의 접근성 트리를 읽습니다. 메시지 내용은 화면 구조를 판별하는 동안 메모리에서만 사용하고 저장·로그·외부 전송하지 않습니다. 다른 앱은 전면 패키지 이름만 확인하고 대화 트리를 읽지 않습니다. 기본 통계 화면에는 개수와 상태만 표시합니다. 진단용 이름 표시를 직접 켠 경우 발신자 이름을 메모리에 유지해 보여주며, 끄면 지웁니다. 구조 진단 파일은 별도 요청/저장 동작이 있을 때만 생성합니다.

설정의 닉네임/방 제목은 앱 내부 SharedPreferences에 평문 JSON으로 저장됩니다. 자동 백업은 끄며 삭제하면 설정도 사라집니다. 사용자가 내보내기를 요청한 JSON에는 숨김 목록과 옵션이 포함됩니다. 파일을 안전하게 보관하세요. 가져온 설정은 필터 OFF 상태로 적용하며 내용을 확인한 후 직접 켜야 합니다.

## 소스 빌드

Android Studio에서 이 `android` 폴더를 열면 됩니다. JDK 17 또는 21, Android SDK Platform 35 및 Build Tools 35.0.0이 필요합니다. 사용한 도구는 AGP 8.9.2 / Kotlin 2.1.20 / Gradle 8.11.1 / JDK 21입니다. Gradle Wrapper에 배포 ZIP의 SHA-256 검증을 설정했습니다.

Windows PowerShell:

```powershell
cd android
.\gradlew.bat :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

Linux/macOS:

```sh
cd android
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

SDK 경로는 Android Studio가 만든 `local.properties` 또는 `ANDROID_HOME`으로 설정하세요. `local.properties`, 빌드 캐시, 서명 키는 저장소에 넣지 않습니다.

일반 설치용 출력: `app/build/outputs/apk/release/app-release.apk`

디버그 빌드가 필요하면 `:app:assembleDebug`를 실행합니다. 출력은 `app/build/outputs/apk/debug/app-debug.apk`입니다. 저장소의 기본 release 서명도 개발용 키를 사용하므로 정식 배포를 준비할 때는 별도로 보관·관리하는 배포 키와 업데이트 계획이 필요합니다.

## 검증 범위

JVM 단위 테스트는 발신자/사진/연속 메시지 연결, 읽지 못한 프로필 경계, 다른 사람의 본문에 포함된 닉네임, 넓은 메시지, 방 범위, 필터 OFF, 편집 입력/명시된 발신 메시지 제외, 현재 스크롤 좌표를 검사합니다. 빌드와 Android Lint는 Android API/리소스/매니페스트 구성도 검사합니다. 이 검증이 실제 카카오톡 접근성 호환성을 입증하지는 않습니다.

실제 기기에서는 다음을 확인하세요.

- [ ] 대상/비대상, 동명이인, 사진·이모티콘·답장·긴 메시지
- [ ] 스크롤·방 전환·가로/세로 회전 후 좌표
- [ ] 가림막 위 클릭·휠/스와이프·메시지 입력
- [ ] 다른 앱·친구 목록·잠금 화면에서 가림막 제거
- [ ] 필터 OFF/접근성 권한 해제 후 제거
- [ ] PC JSON 가져오기/내보내기와 앱 업데이트
